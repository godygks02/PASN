# 활성함수·LayerNorm 프로토타입을 `deepcopy` 대신 **참조**로 심으면 stored bases가 1,832 → **689 (±5%)** 로 줄고, `spikes_per_input`·`by_kind`·ΔPPL은 **bit-identical** 로 유지된다

주장은 **두 부분**이다 — 저장이 줄어든다는 것과 **수치가 한 비트도 안 변한다는 것**.
두 번째가 없으면 이건 그냥 다른 빌드이고, 프리즈 빌드의 헤드라인을 못 물려받는다.

## 근거

**진단은 [`MEMORY_OVERHEAD.md`](../../MEMORY_OVERHEAD.md) §3에 있다.**
[`convert.py:766-806`](../../src/mbe/convert.py#L766)이 활성함수 프로토타입 1개와 LayerNorm
프로토타입 1개를 만든 뒤 나머지 사이트에 **`copy.deepcopy`로 심는다.** 적합 시간은 아끼지만
**저장은 사본 수만큼 그대로 낸다.**

`storage_bytes`가 실제로 그렇게 센다는 것을 직접 확인했다(`MBEConfig(n_basis=4)`):
뉴런 1개 **100 B** · deepcopy 2개 **200 B** · 같은 참조 2번 **100 B**.
그리고 저장소 자체 규약은 이미 반대쪽에 서 있다 — `op_memory` docstring이
*"공유된 basis 집합은 한 번만 청구한다 — 그게 공유의 요점"*
([`op_cost.py:153-162`](../../src/mbe/op_cost.py#L153)). **변환 경로만 그 규약을 안 따른다.**

산술 (E11 `results/bank_usage_audit.json`, 프리즈 빌드 339 사이트, stored bases 기준):

| | 현재 | 참조 공유 시 | 절감 |
|---|---:|---:|---:|
| activation (24 사이트 / 프로토타입 1) | 792 | 33 | 759 |
| layernorm (49 모듈 / 프로토타입 1) | 392 | 8 | 384 |
| matmul + softmax (프로토타입 경로 없음) | 648 | 648 | 0 |
| **합** | **1,832** | **689** | **1,143 (62.4%)** |

교차 검증: `1,832 × 7.35 params/basis ≈ 13,465` 이 프리즈 지문의 `13,472 params` 와 맞는다
(`e7_memory_cost.json` 의 `params_per_basis`). **즉 현재 지문은 24개 사본과 48개 사본을
전부 청구한 값이다.**

**공유가 가능한지 코드로 확인했다** — `SpikingActivation`([`spiking_ops.py:219`](../../src/mbe/spiking_ops.py#L219))과
`SpikingLayerNorm`([`spiking_ops.py:390`](../../src/mbe/spiking_ops.py#L390))은 forward 간
상태를 들고 있지 않고(`@torch.no_grad()` 순수 함수), 사이트별 `γ`·`β`는 래퍼
`_SpikingLayerNormModule` 에 따로 산다. **공유 대상과 사이트별 파라미터가 이미 분리돼 있다.**

## 반증 조건

주장 = `stored_params ≤ 5,500` **그리고** `spikes_per_input` 완전 동일 **그리고**
`|ΔPPL − (−0.1809%)| ≤ 0.0064 pp`(E13이 측정한 박스 간 잡음 바닥).

기준값의 유래: 689 bases × 7.3537 params/basis ≈ **5,067**, 여기에 ±8% 여유.

정의상 같은 텐서를 읽으므로, 다르면 그건 오차가 아니라 배선 오류다.

## 필요한 실험

* **스크립트**: `experiments/shared_refs_gate.py` **(신규)** — 같은 캘리브레이션으로 두 빌드
  (`deepcopy` arm / `shared-ref` arm)를 만들어 ① `stored_bytes`/`stored_params`/`n_primitives`
  ② 사이트별 출력 텐서 최대 절대차 ③ `spikes_per_input`·`by_kind` 를 대조한다.
  **`--build-only` 경로만 쓰므로 GPU 없이 돌아간다.**
* **배선**: [`convert.py:766-806`](../../src/mbe/convert.py#L766)의 `copy.deepcopy(...)` →
  참조 삽입. 사이트별 `weight`/`bias`는 래퍼에 그대로 둔다.
  **플래그로 넣는다**(`ConvertConfig.share_fit_refs`, 기본 `False`) — 기본값을 바꾸면
  프리즈 빌드가 조용히 이동한다. 37 필드 직렬화에 자동 편입된다.
* **설정 / 운영점**: GPT-2-medium · 전역 `T=16` · backend `mbe_pasn` · 변환 경로 arm ·
  stride 1024. **프리즈 빌드로 돌린다** — 이 카드는 프리즈 빌드가 기준선이고,
  게이트 자체가 "프리즈 빌드와 bit-identical인가"다.
* **비용**: 빌드 대조는 **로컬 CPU 약 1 h**(빌드 2회). ΔPPL 재현은 **GPU 1점 ≈ 2.4 h**.
  R1–R3가 로컬에서 깨지면 **GPU는 쓰지 않는다.**
* **산출 레코드**: `results/e21_shared_refs.json` (신규 파일 — 기존 레코드 수정 금지) +
  지문 대조표 1장(`deepcopy` / `shared-ref` / 프리즈 지문 3열).

## 이 실험이 실패하는 방식

**(a) 계측이 사이트별 귀속을 잃는다 — 코드로 확인했다.**
[`_spiking_primitives`](../../src/mbe/convert.py#L816)는 *"Neurons shared by object identity
are listed once"* 라고 명시하며 **id로 유일화한다.** 그러므로 참조 공유 후에는:

* `n_primitives`가 **339 → 약 172로 떨어진다** (활성함수 23개 + LN 프리미티브 144개가 접힘).
  **지문 세 필드 중 하나가 이렇게 바뀌므로, 이 카드는 지문 갱신 없이는 닫히지 않는다.**
* 프로브는 뉴런당 **한 번** 설치되지만 **호출마다 발화**하므로 `total_spikes`와
  `spikes_per_input`은 보존된다 — R2가 이걸 검사한다.
* 다만 24개 사이트의 스파이크가 **한 이름 아래로 합쳐진다.** 사이트별·층별 분해
  (E0의 층 프로파일, `act_spikes_per_input`)를 다시 뽑으려면 계측 경로를 먼저 고쳐야 한다.

**⛔ 그래서 공유는 반드시 "같은 op kind 안에서만" 한다.** 서로 다른 kind가 한 뉴런을
공유하면 `by_kind`(= E0의 op 예산 표, `matmul 48.3% / softmax 33.5% / …`)가 **하나의 kind로
합쳐져 표 자체가 틀린다.** 이 카드의 범위(활성함수 24개끼리, LayerNorm 49개끼리)는 그
제약을 지키지만, 나중에 E24가 항등원을 op 경계 너머로 공유하면 **그때는 계측을 먼저
고쳐야 한다.**

**(b) 절감을 기여로 파는 것.** 이건 방법 개선이 아니라 **과대 계상의 정정**이다.
"PASN이 메모리를 62% 줄였다"고 쓰는 순간 리뷰어가 이전 숫자의 출처를 묻는다.
정확한 문장은 *"이전 보고는 사이트별 사본을 중복 청구했다"*이다.

**(c) op 층위 표가 바뀔 거라는 오해.** 피드백 4 §4.1의 op별 배수
(`fp_multiply` 9.09× 등)는 **단일 사이트 op 비교**라 이 변경과 무관하다. 바뀌는 것은
**네트워크 총량**(E7)과 **파라미터 축**(E5)뿐이다. 두 표를 같이 고치면 틀린다.

**(d) 바이트가 줄어도 접근 에너지는 안 준다.** element-stationary에서 PASN의 파라미터
읽기는 여전히 원소당 발생한다(E7 `pasn_param_reads = 5.56e9`). **메모리 축과 에너지 축은
다른 축이다.** 이 카드는 에너지에 대해 아무것도 주장하지 않는다 — 그건 E18이 한다.

**(e) 바이트 환산을 선형으로 가정하는 것.** `29.4 B/basis`는 평균이다. 라우터 경계·예산
테이블처럼 basis에 비례하지 않는 항이 있으면 절감이 62.4%보다 작다. **그래서 이 카드의
게이트는 예측 비율(62.4%)이 아니라 측정 절대값(`stored_params ≤ 5,100`)이다.**

**(f) 프리즈 규칙과의 충돌을 조용히 넘어가는 것.** 통과하면 지문
(`53,888 B / 13,472 p / 339 prims`)이 바뀐다. CLAUDE.md의 프리즈 인용 규칙과
`research/tools/check_build.py`가 전부 그 지문 위에 서 있다. **지문 갱신은 사람 승인
사항이고, 승인 전까지 새 지문을 논문·발표에 쓰지 않는다.**
