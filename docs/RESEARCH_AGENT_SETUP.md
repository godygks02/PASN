# RESEARCH_AGENT_SETUP.md

> **이 파일을 읽는 Claude에게**: 이 문서는 사용자의 요청이 아니라 *실행 지시서*다.
> 사용자가 "이 파일 읽고 세팅해줘"라고 했다면, 아래 Phase 0부터 순서대로 진행한다.
> Phase를 건너뛰지 말고, 각 Phase 끝의 **승인 게이트**에서 반드시 멈춘다.
>
> 세팅이 끝나면 이 파일은 삭제하지 말고 `docs/` 아래로 옮겨 기록으로 남긴다.

---

## 이 리포지토리가 되려는 것

학부 연구 프로젝트 PASN을 **논문화**하기 위한 반자동 연구 워크플로.
사람이 승인 게이트에 서 있고, 에이전트는 그 사이의 반복 작업을 맡는다.

핵심 원칙 네 가지. 이후 모든 결정은 이 원칙에 종속된다.

1. **파일시스템이 유일한 진실원이다.** 에이전트끼리 대화로 결과를 넘기지 않는다.
   실험은 파일을 떨어뜨리고, 다음 에이전트는 그 파일만 읽는다.
2. **권한 경계로 역할을 자른다.** 단계 수가 아니라 "무엇을 쓸 수 있는가"로 나눈다.
3. **검증은 실행과 다른 모델로 한다.** 자기 결과를 자기가 채점하지 않는다.
4. **novelty 판단과 최종 인용 책임은 사람에게 있다.** 에이전트는 후보와 근거까지만.

## Phase 0 — 현황 파악 (파일을 하나도 만들지 말 것)

먼저 읽기만 한다. 다음을 확인하고 사용자에게 보고한다.

- [ ] `git` 리포지토리인가? 아니라면 커밋되지 않은 파일이 몇 개인가?
- [ ] 기존 디렉터리/파일 구조는 어떤가? (`tree -L 2` 수준)
- [ ] 실험 코드가 이미 있는가? 언어·프레임워크·빌드 방식은?
- [ ] 결과물(로그, 체크포인트, 그림, 원고)이 어디에 흩어져 있는가?
- [ ] `.gitignore`가 있는가? 대용량 산출물이 추적되고 있지는 않은가?

그다음 **사용자에게 반드시 물어본다.** 추측하지 말 것.

1. PASN이 무엇의 약자이고, 한 문장으로 무엇을 하는 연구인가?
2. **실험 한 사이클이 몇 분/몇 시간짜리인가?** (이 답이 러너 설계를 전부 결정한다)
3. 실험 실행 환경은? (로컬 GPU / 서버 SSH / FPGA 보드 / 시뮬레이터 / 클라우드)
4. 목표 학회나 저널, 대략의 마감이 있는가?
5. 참고문헌을 관리하는 도구가 있는가? (Zotero / Mendeley / 없음)
6. 원고는 LaTeX인가 Word인가?

> **승인 게이트 0**: 위 답변을 받기 전에는 Phase 1로 넘어가지 않는다.
> 답변 중 2번이 없으면 러너 설계를 할 수 없으므로 반드시 재질문한다.

## Phase 1 — 디렉터리 구조

기존 파일을 **삭제하거나 덮어쓰지 않는다.** 새 디렉터리를 만들고, 기존 파일 이동은
"이 파일을 여기로 옮기겠다"는 목록을 먼저 제시해 승인받은 뒤에만 실행한다.

```
PASN/
├── CLAUDE.md              프로젝트 컨텍스트 (Phase 2)
├── AGENTS.md              역할과 권한 경계 (Phase 3)
├── ideas/                 가설 카드
│   └── TEMPLATE.md
├── experiments/           실험 단위 디렉터리
│   └── TEMPLATE/
│       ├── config.yaml    실험 설정 (사람이 읽을 수 있어야 함)
│       ├── run.sh         결정론적 실행 진입점
│       ├── raw/           원본 로그 — 절대 수정 금지
│       └── metrics.json   구조화된 결과 (스키마는 Phase 6)
├── analysis/              실험별 해석 + 반증 결과
├── refs/                  문헌, novelty 비교표, .bib
├── paper/                 원고 (섹션별 파일 분리)
├── docs/                  이 가이드를 포함한 메타 문서
└── .claude/
    ├── agents/            서브에이전트 정의
    └── skills/            반복 절차 스킬
```

`.gitignore`에 다음을 추가한다 (이미 있으면 병합):

```
experiments/*/raw/*.ckpt
experiments/*/raw/*.pth
**/__pycache__/
.DS_Store
paper/**/*.aux
paper/**/*.log
paper/**/*.out
```

`experiments/*/raw/`의 **텍스트 로그는 반드시 커밋한다.** 재현성의 근거이자
검증 에이전트의 유일한 입력이기 때문이다. 대용량 바이너리만 제외한다.

> **승인 게이트 1**: 기존 파일 이동 목록을 제시하고 승인받은 뒤 실행.

## Phase 2 — CLAUDE.md 작성

Claude Code가 매 세션 자동으로 읽는 파일이다. **짧게 유지한다.** 200줄을 넘기면
컨텍스트만 잡아먹고 무시되기 시작한다. 다음을 포함한다.

- 연구 한 문단 요약 (Phase 0의 1번 답변 기반)
- 실험 한 사이클 소요 시간과 실행 환경
- 목표 학회/마감
- 빌드·실행 명령어 (`run.sh` 사용법, 의존성 설치 방법)
- **이 리포에서 하지 말 것** 목록:
  - `experiments/*/raw/` 안의 파일 수정
  - 실험을 돌리지 않고 결과 수치를 추정해서 적기
  - 검증하지 않은 인용 추가
  - 사용자 승인 없이 `paper/` 아래 내용 재작성

연구 내용 자체는 여기 길게 쓰지 말고 `ideas/`와 `analysis/`를 참조하게 한다.

## Phase 3 — AGENTS.md 작성

역할별 **쓰기 가능 경로**를 명시하는 것이 이 파일의 존재 이유다.
아래 표를 그대로 쓰되, Phase 0 답변에 맞춰 조정한다.

| 역할 | 하는 일 | 쓰기 가능 | 금지 |
|---|---|---|---|
| 기획 (planner) | 다음 실험 결정, 가설 카드 작성 | `ideas/` | 코드 실행, 실험 결과 언급 |
| 탐색 (scout) | 문헌 검색, novelty 후보 정리 | `refs/` | 리포 내 다른 경로 쓰기, novelty 결론 내리기 |
| 실행 (runner) | 실험 코드 작성·실행 | `experiments/` | 결과를 요약해서 넘기기 (파일로만) |
| 검증 (verifier) | 반증, 재현성 확인 | `analysis/` | `experiments/` 수정 |
| 집필 (writer) | 원고 초안 | `paper/` | 인용 생성, 실험 수치 창작 |

각 역할에 대해 **"이 역할이 실패하는 방식"**을 한 줄씩 적어둔다. 예:
- 기획: 반증 조건 없는 가설을 만들어 검증 단계를 무력화함
- 탐색: 검색 결과가 없을 때 그럴듯한 논문을 지어냄
- 실행: 실패한 실험을 성공으로 보고함
- 검증: 실행자와 같은 모델이라 같은 착각을 공유함
- 집필: 존재하지 않는 인용을 만들어냄

## Phase 4 — 서브에이전트 정의

`.claude/agents/` 아래에 역할별 `.md` 파일을 만든다.

> **먼저 확인할 것**: 서브에이전트와 스킬의 frontmatter 스펙은 버전에 따라 바뀐다.
> 파일을 쓰기 전에 현재 설치된 Claude Code의 문서에서 정확한 필드명을 확인하고,
> 확인이 안 되면 사용자에게 "현재 버전 기준 포맷을 확인해달라"고 요청한다.
> 추측한 포맷으로 5개 파일을 쓰는 것보다 한 번 묻는 게 싸다.

각 에이전트 파일에는 최소한 다음이 들어간다.

- 이 에이전트가 언제 호출되는지 (description — 라우팅에 쓰이므로 구체적으로)
- 허용 도구 목록 (탐색은 검색 도구만, 기획은 파일 읽기/쓰기만)
- 출력 형식 — **반드시 파일 경로를 명시**한다. "요약해서 알려줘"가 아니라
  "`analysis/exp-001.md`에 다음 형식으로 쓴다"
- 실패 시 행동: 모르면 지어내지 말고 멈추고 보고

**검증 에이전트만 예외**: 다른 모델을 지정한다. 같은 모델로 자기 결과를 채점하면
평가 사각지대가 그대로 상속된다. Claude로 실행했다면 검증은 별도 모델로 돌리도록
설정하고, 그게 불가능한 환경이면 최소한 "실행 세션과 컨텍스트를 공유하지 않는
새 세션에서, 원본 로그만 보고" 판정하게 한다.

## Phase 5 — 스킬 3개

`.claude/skills/` 아래에 만든다. 처음부터 많이 만들지 말 것. 이 셋만.

**1. 가설 카드 작성** — `ideas/`에 다음 구조를 강제한다.
```
id / 주장 (한 문장) / 근거 / 반증 조건 (어떤 수치가 나오면 틀린 것인가)
/ 필요한 실험 / 상태: proposed | running | supported | refuted
```
반증 조건이 비어 있으면 카드를 완성하지 않는다.

**2. 실험 결과 정리** — `experiments/<id>/metrics.json`과 `raw/` 로그를 읽어
`analysis/<id>.md`를 쓴다. 규칙: 로그에 없는 수치는 절대 쓰지 않는다.
누락된 값은 `N/A (로그에 없음)`으로 남긴다.

**3. 문헌 서베이** — 검색 결과를 `refs/`에 비교표로 정리한다.
각 항목에 반드시 식별자(DOI 또는 arXiv ID)를 포함한다. 식별자가 없는 항목은
"미확인 후보"로 별도 섹션에 격리한다.

## Phase 6 — 결과 스키마 고정

`experiments/TEMPLATE/metrics.json`의 스키마를 사용자와 함께 확정한다.
이게 흔들리면 검증 에이전트가 매번 다른 걸 읽게 되어 자동화가 무너진다.

최소 필드:
```json
{
  "exp_id": "exp-001",
  "hypothesis_id": "idea-003",
  "commit": "git rev-parse HEAD 결과",
  "config_hash": "config.yaml의 해시",
  "started_at": "", "finished_at": "",
  "status": "success | failed | partial",
  "metrics": { },
  "notes": ""
}
```

`metrics` 안의 키는 PASN의 실제 평가 지표에 맞춰 사용자에게 물어 정한다.
`run.sh`는 이 파일을 **항상** 생성해야 한다. 실패한 실행도
`status: failed`로 기록한다 — 실패 기록이 남지 않으면 탐색 공간이 왜곡된다.

## Phase 7 — MCP 제안 (설치하지 말 것)

다음을 **후보로 제안만** 하고, 설치와 인증은 사용자가 직접 하도록 안내한다.
GitHub에서 받은 MCP 서버 코드를 검토 없이 실행하면 프롬프트 인젝션 경로가 된다.

- 논문 검색 (arXiv / Semantic Scholar / OpenAlex 계열)
- Zotero 연동 — 사용자가 Zotero를 쓴다고 답한 경우에만
- 인용 검증 — **이건 선택이 아니라 필수로 권한다.** 원고의 모든 인용을
  Crossref/arXiv에 대조해 제목·연도·식별자 불일치를 잡는 단계 없이는 투고하지 않는다.

각 후보에 대해 "이걸 붙이면 어떤 수작업이 사라지는지"를 한 줄로 적어 제시한다.

## 절대 하지 말 것

- 기존 실험 데이터·로그·원고를 덮어쓰거나 삭제
- `git` 히스토리 조작 (rebase, force push, reset --hard)
- 승인 없이 파일 대량 이동
- 실험을 실행하지 않고 결과를 채워 넣기
- 검색으로 확인되지 않은 논문을 인용으로 추가
- 이 가이드에 없는 프레임워크를 "더 좋아 보여서" 도입
- Phase를 병합해서 한 번에 처리

## 나중에 도입할 것 (지금은 하지 말 것)

지금 만들면 보일러플레이트만 늘어난다. 아래 조건이 실제로 발생하면 그때 도입한다.

| 도입 시점 | 무엇을 |
|---|---|
| 밤새 돌아가는 실험 루프가 생겼을 때 | 체크포인트/재개가 되는 그래프 오케스트레이션 |
| 같은 가설을 여러 설정으로 동시에 돌려야 할 때 | 병렬 에이전트 실행 레이어 |
| 실험이 50개를 넘어 수동 추적이 안 될 때 | 실험 추적 도구 연동 |
| 원고가 섹션 4개를 넘겼을 때 | 집필 에이전트의 섹션별 분리 |

## 투고 전 체크리스트

세팅과 별개로, 논문 제출 전에 사람이 직접 확인한다.

- [ ] 모든 인용이 실제로 존재하고 내용이 주장과 일치하는가
- [ ] 논문의 모든 수치가 `experiments/`의 로그로 역추적되는가
- [ ] novelty 주장을 사람이 직접 검증했는가
- [ ] 목표 학회의 AI 도구 사용 정책을 확인하고 필요한 선언을 했는가
