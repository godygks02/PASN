# Phase 3 — Spiking Transformer primitives from MBE neurons

This phase assembles the conversion framework's non-spiking components as
spike-driven operations built from calibrated MBE neurons, and verifies each
against the exact PyTorch op on CPU. Code:
[`src/mbe/spiking_ops.py`](src/mbe/spiking_ops.py); verification:
[`experiments/verify_phase3.py`](experiments/verify_phase3.py); tests in
[`tests/test_mbe_neuron.py`](tests/test_mbe_neuron.py).

## 1. Spiking FP multiplication (Eq. 9–12, 22–27, Fig. 9)

Each operand is turned into a spike train by an identity-calibrated neuron
`MBE_Id` (no bias, so `reconstruct(x) = Σ_{n,t} a_{n,t} s_n[t] ≈ x` is a pure
spike sum). The product is the Hadamard sum of the **intensity outer product**
`D = a ⊗ a′` (input-independent, precomputable) and the **spike outer product**
`S = b(x1) ⊗ b(x2)` (binary):

```
x1·x2 ≈ Σ_{k,l} D_{k,l} · S_{k,l}     (k,l index the flattened (n,t) slots)
```

That double sum is separable, so it equals `recon(x1)·recon(x2)` — used for bulk
evaluation, while `multiply_outer` builds the explicit `D⊙S` matrix to confirm
equivalence. Signed operands use `x = relu(x) − relu(−x)` (four non-negative
reconstructions), the signed-magnitude scheme of
[`PASN_method.md`](PASN_method.md) §6.

## 2. Spiking Softmax (Eq. 13, Table VIII)

```
e^x = 2^{x·log2 e} = 2^{⌊·⌋} · 2^{frac}      frac∈[0,1) → MBE_exp (2^x on [0,1])
                     └ exact power-of-two shift
S   = Σ e^x                                    spike accumulation (exact reduce)
1/S : S = m·2^e  (m∈[0.5,1))  → 1/m via MBE_inv (1/x on [0.5,1]), ×2^{−e}
out = e^x · (1/S)                              spiking FP multiply
```

## 3. Spiking LayerNorm (Fig. 5c)

```
μ            = mean(x)                          exact reduce
(x−μ)²/n     = spiking FP-mult(dev,dev)/n       (1/n folded into intensity D)
1/√(var)     : var = M·2^E, E made even (parity fix); 1/√M via MBE_invsqrt
               (1/√x on [0.5,2]), ×2^{−E/2}
normalise    = (x−μ) · invstd                   spiking FP multiply (signed)
affine       = γ·(·) + β
```

## 4. Verification results (CPU, vs exact PyTorch ops)

`spike-mult` = every multiply is the spike outer-product; `exact-mult` isolates
the error of the other MBE primitives (exp/inv/invsqrt) by using an exact
multiply. Generated by `experiments/verify_phase3.py`.

| Operation | mean \|err\| | max \|err\| | notes |
|---|---|---|---|
| FP-mult (non-negative) | 5.1e-2 | 3.8e-1 | ~1.9% relative; operands in [0,8] |
| FP-mult (signed) | 2.9e-2 | 2.3e-1 | operands in [−6,6] |
| outer-product `D⊙S` | — | — | **exactly equals** separable form (16.831 = 16.831) |
| Softmax (spike-mult) | 6.2e-4 | 5.5e-3 | row-sums ≈ 0.997 |
| Softmax (exact-mult) | 3.2e-4 | 5.0e-3 | exp + reciprocal only |
| LayerNorm (spike-mult) | 4.5e-3 | 3.4e-2 | γ,β affine included |
| LayerNorm (exact-mult) | 1.4e-3 | 3.3e-2 | inverse-sqrt only |

**Reading:**

- The spike-driven Softmax and LayerNorm reproduce the exact ops to ~1e-3
  (mean), and Softmax rows stay normalised (Σ≈1) purely from the spike/IEEE-754
  decomposition. This confirms the decompositions in Table VIII / Fig. 5c are
  correctly assembled.
- The dominant error source is `MBE_Id`'s identity reconstruction (the FP
  multiply). It scales with the operand range; Softmax/LayerNorm keep operands in
  small, well-conditioned ranges ([0,1], mantissa [0.5,2]) so their errors are an
  order of magnitude smaller than a raw wide-range FP-mult.
- The explicit `D⊙S` outer product matches the separable reconstruction product
  exactly, confirming the spike-driven multiplication is implemented as the
  paper's Hadamard-product formulation, not merely a scalar multiply.

## 5. Scope / caveats

This is a **numerical, single-op verification** of the spiking primitives on CPU.
It does not yet wire them into a full Transformer block, nor run the end-to-end
conversion on real ANN weights (ImageNet/NLU/NLG) — that is Phase 4–5 (GPU /
vast.ai). The primitives reuse the same MBE implementation as Phase 1–2, so they
inherit its documented design choices (per-basis α, closed-form readout, signed
split; see [`MBE_RESULTS.md`](MBE_RESULTS.md)).
