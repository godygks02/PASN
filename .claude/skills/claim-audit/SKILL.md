# claim-audit — 수치가 레코드로 역추적되는가

## 왜 이 스킬이 있나

2026-08-14 랩미팅 피드백 4개 중 3개는 **이미 저장소 안에 🔴로 기록돼 있던 것**이었다.
데이터가 없어서 못 말한 게 아니라, 발표에 안 올라갔다. 그리고 08-10에는 헤드라인
레코드가 현재 코드가 만드는 빌드가 아니라는 게 뒤늦게 드러나 E0 전체가 생겼다.

두 사고의 공통 원인은 하나다: **수치와 그 수치의 출처가 분리됐다.**

## 절차

### 1. 수치를 전부 뽑는다

대상 문서에서 수치 주장을 하나씩 뽑는다. 표는 셀 단위로 쪼갠다.
`5.27×`, `−0.19%`, `53,888 B`, `86.5%` 같은 것 전부.

각각에 대해 세 가지를 묻는다:

- **출처 레코드가 있는가?** 경로와 tag
- **어느 빌드인가?** beta(프리즈) / no-beta / 변종
- **어느 운영점인가?** T, arm, stride

### 2. 빌드를 기계로 판정한다

```bash
python research/tools/check_build.py results/<레코드>.json
```

| 표시 | 뜻 | 조치 |
|---|---|---|
| `OK` | 프리즈 빌드 | 그대로 인용 가능 |
| `NAME` | no-beta 빌드 | **빌드 이름을 반드시 붙인다** |
| `??` | 변종 | 헤드라인으로 쓸 수 없다 |
| `--` | 다른 모델/ANN 기준런 | 대조 대상 아님 |

### 3. 위험한 조합을 먼저 본다

이 프로젝트에서 실제로 일어난 것들이다. 발견하면 즉시 표시한다.

- **`−0.14%` + `53,888 B`** — 다른 빌드의 수치가 한 문장에 있다
- **`49,952 B` / `12,488 p`** — no-beta 빌드인데 이름이 안 붙었다
- **`86.5%`(어텐션 비중)** — per-bank `T_j` arm 값이다. 전역 `T=16`에서는 **81.8%**
- **op마다 최선 arm을 골라 만든 범위** — 진단용이지 헤드라인이 아니다
- **논문과의 절대 정확도/perplexity 직접 비교** — 하면 안 된다
- **`T`를 가로지른 비교** — 저쪽 `T=16` vs 우리 `T=4`는 결과가 아니라 트레이드다
- **등정확도가 아닌 비용 비교** — 정확도를 스파이크로 산 것일 수 있다

### 4. 교차모델 검증에 넘긴다

의심스러운 주장은 Codex로 판정한다. 한 문장씩:

```bash
python research/tools/verify.py --claim "<주장 한 문장>" results/<레코드>.json
```

여러 레코드를 걸치는 주장이면 전부 넘긴다 — 빌드 혼합은 그래야 보인다.

### 5. 같은 JSON 안의 모순을 찾는다

헤드라인 수치 옆에 **그것과 모순되는 수치가 같은 파일에 들어 있는 경우**가 있었다.
`5.27×`(범위 아티팩트) 옆에 PASN 엄격 계상 2.871 mJ가 있고, 이건 MBE 스파이크-온리
1.413 mJ보다 **2.03× 나쁘다**. 레코드를 헤드라인 필드만 보고 닫지 마라.

## 출력

`research/verdicts/<날짜>-<문서명>-audit.md`:

```markdown
# <문서> 수치 감사 — YYYY-MM-DD

| # | 수치 | 위치 | 출처 레코드 | 빌드 | 운영점 | 판정 |
|---|---|---|---|---|---|---|
| 1 | −0.19% | 슬라이드 4 | freeze_e1.json[0] | beta OK | T=16, unif | ✅ |
| 2 | 5.27× | 슬라이드 9 | op_pareto_merged.json | ?? | arm 불명 | 🔴 |

## 🔴 고쳐야 할 것
## 🟡 빌드 이름을 붙여야 할 것
## ⚪ 레코드가 아예 없는 것
```

**레코드가 없는 수치는 `N/A (레코드 없음)`으로 남긴다.** 그럴듯한 값을 채우지 마라 —
그게 이 감사가 막으려는 바로 그것이다.

## 잊지 말 것

약점을 찾는 게 목적이다. 통과한 항목을 길게 나열하지 말고, **🔴와 ⚪를 먼저** 올린다.
이미 아는 약점이 발표 표면으로 올라가지 않는 것이 이 프로젝트의 반복된 실패다.
