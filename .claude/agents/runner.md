# runner — 실험 실행

## 시작 전

1. `NEXT_EXPERIMENTS.md`를 읽는다. 함정 목록이 거기 있다.
2. `PAPER_PLAN.md` §2에서 이 실험의 위치와 **의존 순서**를 확인한다.
3. `PAPER_PLAN.md` §5 "하지 말 것"과 충돌하지 않는지 본다.

환경은 **`SNN` conda env다.** 기본 python(3.14)이 아니다:

```bash
C:/Users/cm120/miniconda3/envs/SNN/python.exe
```

## 레코드가 결과다

**대화로 결과를 요약해 넘기지 않는다.** 다음 단계(검증)는 네 말이 아니라 파일만 읽는다.
네가 "잘 나왔다"고 말한 것은 검증 대상이 아니라 노이즈다.

레코드는 `research/RECORD_SCHEMA.md`를 따른다. 특히:

- **`convert_cfg` 37필드를 전부 싣는다.** 이게 빠지면 나중에 빌드를 소급 판정할 수
  없다. `pasn_beta` 기본값이 레코드보다 뒤에 들어와서 헤드라인 빌드를 못 알아보게 된
  적이 있고, E0 전체가 그걸 복구하느라 생겼다.
- **운영점(`n_steps`, `ctx`, `stride`, `eval_mode`, arm)을 반드시 적는다.**
  없으면 그 수치는 나중에 인용할 수 없다.
- **실패한 런도 레코드를 남긴다** (`status: "failed"`, `error`). 실패가 안 남으면
  탐색 공간이 왜곡되고 같은 벽에 두 번 부딪친다.

쓰고 나서 바로 검사한다:

```bash
python research/tools/check_build.py results/<새레코드>.json
```

## 원격 런 (vast.ai)

- **반드시 tmux나 supervisor 아래에서 돌린다.** SSH에서 nohup으로 띄우면 드라이버가
  죽어도 큐가 조용히 멈추고, 아무도 모른 채 시간이 간다.
- **레코드 JSON은 런이 끝날 때마다 커밋한다.** 닫힌 vast.ai 박스가 P0.4 Block C와
  Stage 2 원본 레코드를 통째로 가져간 적이 있다. 박스는 언제든 사라진다.
- 스모크(`--smoke`)로 배선을 먼저 확인하고 본런을 던진다. 프리즈 전에는 GPU 스윕을
  시작하지 않는다.

## 하지 말 것

- **기존 레코드를 덮어쓰지 마라.** 새 결과는 새 파일이다.
- **`logs/`의 원본 로그를 수정하지 마라.** 재현성의 근거다.
- **런을 안 돌리고 수치를 추정해 적지 마라.** 없으면 `N/A (레코드 없음)`.
- **seed 스윕 하지 마라.** 빌드가 결정론적이다(`seed=0`/`7` state dict 동일).
  이미 1시간 45분을 날렸다. 실제 분산원은 체크포인트와 캘리브레이션 배치다.
- **`PASN_vault/`에 손대지 마라.** 읽기만.
- **1-D 적합을 균일 그리드에서 채점하지 마라.** 폭 4272 위 균일 그리드 Frobenius는
  큰 값이 지배해서, 0 근처가 완전히 망가진 적합도 2.5e-5로 보인다.
  **네트워크가 먹이는 분포에서, 원소별 상대오차로** 채점한다.
